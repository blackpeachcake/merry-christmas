# 에디터 실험 1단계 — 인스타 스토리식 캔버스 에디터 설계

- 작성일: 2026-11-24
- 이슈: #11
- 관련: Discussion #4(1차 스펙 확정 코멘트), 세팅 PR #10

## 1. 목적과 범위

실시간 동시 편집을 붙이기 전에, **혼자 쓰는 에디터**로 react-konva · Yjs · 제스처 조합이 모바일에서 원하는 수준으로 동작하는지 검증한다. 결과는 2단계(동시 편집)와 BE 논의의 근거가 된다.

**기준:** 최대한 인스타그램 스토리 편집기처럼 동작한다.

### 범위 안

- `/editor` 흐름: 비율 선택 → 배경 선택 → 에디터
- Y.Doc 문서 + IndexedDB 저장(새로고침 유지)
- 텍스트: 인스타식 전체 화면 입력
- 스티커: 앨범에서 고르기, 붙여넣기(누끼)
- 제스처: 드래그, 핀치·회전, 잡으면 맨 위로, 휴지통 삭제, 가운데 가이드·스냅
- PC 마우스용 크기·회전 핸들
- 실행 취소 / 다시 실행
- PNG 저장
- 자동 테스트 + 실기기 확인 결과 문서

### 범위 밖

- WebSocket 동시 편집, 접속자 표시, 소프트 잠금 → 2단계
- 업로드 서버, 로그인, 방, 초대 → BE 논의 후
- 디자인 시스템 → 디자인 단계 (이번 UI는 기능 검증용 최소 스타일)
- 앱 내 배경 제거(누끼) AI 모델

## 2. 기술 선택

| 영역        | 선택                                                                                             | 이유                                                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 캔버스      | **react-konva**                                                                                  | 핸들(Transformer) 기본 제공, `toDataURL`로 iOS에서도 안정적인 PNG 저장, React 선언형과 궁합. DOM 방식은 iOS 이미지 저장이 불안정, Fabric은 명령형이라 Yjs 상태 기준 구조와 맞지 않음 |
| 문서 상태   | **Yjs** (`yjs`)                                                                                  | 2단계 동시 편집에 그대로 이어짐                                                                                                                                                      |
| 로컬 저장   | `y-indexeddb`                                                                                    | 서버 없이 새로고침 유지                                                                                                                                                              |
| 실행 취소   | `Y.UndoManager`                                                                                  | 내 변경만 되돌림 → 2단계에서도 유지                                                                                                                                                  |
| UI 상태     | `zustand`                                                                                        | 선택·모드 등 문서가 아닌 상태                                                                                                                                                        |
| 제스처      | `@use-gesture/react`                                                                             | 두 손가락 핀치·회전                                                                                                                                                                  |
| 이미지 압축 | `browser-image-compression`                                                                      | 긴 변 2048px, **PNG/WebP 유지(투명도 보존)**                                                                                                                                         |
| 토스트      | `sonner`                                                                                         | 에러·안내                                                                                                                                                                            |
| 폰트        | Pretendard(로컬 woff2) + `next/font/google`(Gowun Batang, Jua, Black Han Sans, Nanum Pen Script) | 성격이 다른 무료(OFL) 5종. 디자인 단계에서 교체 가능                                                                                                                                 |

**한글 폰트 로딩:** 영문만 preload하고 한글은 실제 쓰는 글자가 든 파일만 그때 받는다. 이유와 검토한 선택지는 `docs/decisions/0001-korean-font-loading.md`.

### Next.js와의 관계

Konva·Yjs·IndexedDB는 브라우저 전용이다. 에디터는 `"use client"` 파일 안에서 `next/dynamic(..., { ssr: false })`로 불러와 **서버 렌더링에서 제외**한다(Next 16 문서: `ssr: false`는 클라이언트 컴포넌트에서만 허용).

## 3. 구조

```
apps/web/src/
  app/editor/
    page.tsx               서버 컴포넌트 (껍데기)
    editor-loader.tsx      "use client" + dynamic(ssr:false)
  features/editor/
    model/                 React와 무관한 순수 로직 (단위 테스트 대상)
      types.ts             Ratio, Background, Block 타입
      constants.ts         비율별 캔버스 크기, 폰트 5종, 색 팔레트
      doc.ts               Y.Doc 생성·초기화, 문서 → 스냅샷 변환
      operations.ts        addText, addSticker, updateBlock, bringToFront,
                           removeBlock, setBackground
      geometry.ts          화면 맞춤 배율, 중앙·회전 스냅, 휴지통 판정, 핀치 계산
    state/
      useEditorDoc.ts      Y.Doc + IndexedDB + UndoManager 수명 관리
      useDocSnapshot.ts    Y.Doc 변경 → React 리렌더 (useSyncExternalStore)
      uiStore.ts           Zustand: 선택 블록, 모드, 드래그 중, 휴지통 위 여부
    canvas/                Konva 렌더링
      EditorStage.tsx, BackgroundLayer.tsx, TextNode.tsx, StickerNode.tsx,
      CenterGuides.tsx, SelectionHandles.tsx (PC 전용)
    gestures/              포인터·핀치 → operations 호출
    ui/
      SetupFlow.tsx        비율 → 배경 선택
      TopBar.tsx           ✕, ↶ ↷, 배경, 텍스트, 스티커, 저장
      TextComposer.tsx     전체 화면 텍스트 입력
      StickerSheet.tsx     앨범 / 붙여넣기
      BackgroundSheet.tsx  단색 / 사진
      TrashZone.tsx
    media/
      loadImage.ts         파일·클립보드 → 압축 → data URL
      fonts.ts             폰트 로드 대기
    export/exportPng.ts
```

**원칙**

- 화면(Konva·React)은 문서를 **읽기만** 하고, 모든 변경은 `operations.ts`를 거친다.
- 2단계에서 동시 편집을 붙일 때 바뀌는 곳은 `useEditorDoc`(provider 연결)뿐이어야 한다.
- 타입은 `apps/web` 안에 둔다. `packages/shared` 이동은 2단계 BE 논의 때 정한다.

## 4. 데이터 모델 (Y.Doc)

```ts
doc.getMap('meta')
  ratio: '9:16' | '4:5' | '1:1' | '16:9'           // 생성 후 변경 불가
  background: { type: 'color'; color: string }     // '#RRGGBB'
            | { type: 'image'; src: string }        // 1단계: data URL

doc.getMap('blocks')   // Y.Map<id, Y.Map>  — 블록 하나 = Y.Map 하나 (필드 단위 병합)
doc.getArray('order')  // Y.Array<id>        — 앞 = 맨 아래, 뒤 = 맨 위
```

블록 필드 (인스타처럼 크기 대신 **배율**로 저장):

| 필드              | 텍스트 | 스티커 | 설명                                                     |
| ----------------- | ------ | ------ | -------------------------------------------------------- |
| `id`, `type`      | ✓      | ✓      | `'text'` / `'sticker'`                                   |
| `x`, `y`          | ✓      | ✓      | 요소 **중심**, 논리 좌표                                 |
| `rotation`        | ✓      | ✓      | 도(degree)                                               |
| `scale`           | ✓      | ✓      | 핀치 배율                                                |
| `text`            | ✓      |        |                                                          |
| `fontId`          | ✓      |        | 폰트 5종 중 하나                                         |
| `fontSize`        | ✓      |        | 입력 화면 슬라이더 값 (기본 배율 1에서의 크기)           |
| `color`           | ✓      |        |                                                          |
| `align`           | ✓      |        | `'left'` / `'center'` / `'right'`                        |
| `textBg`          | ✓      |        | `'none'` / `'translucent'` / `'solid'` (인스타 "A" 버튼) |
| `src`             |        | ✓      | 1단계: data URL                                          |
| `width`, `height` |        | ✓      | 원본 비율 계산용                                         |

**논리 캔버스 크기:** 9:16 = 1080×1920, 4:5 = 1080×1350, 1:1 = 1080×1080, 16:9 = 1920×1080. 화면에는 기기에 맞춰 축소해서 보여준다.

**1단계 한계:** 스티커·배경 사진은 data URL을 문서에 그대로 넣는다. 2단계에서 업로드 서버가 생기면 URL로 바꾼다.

## 5. 화면과 조작

### 흐름

1. **비율 선택:** 카드 4개
2. **배경 선택:** 탭 — 단색(팔레트 + 직접 고르기) / 사진(앨범)
3. **에디터:** 이미 문서가 있으면(IndexedDB) 1·2를 건너뛰고 바로 에디터

### 에디터 화면

```
┌──────────────────────────┐
│ ✕   ↶ ↷     🎨  Aa  🖼  ⬇ │  상단 바
│                          │
│   캔버스 (화면에 맞춰 축소)   │
│                          │
│           🗑              │  드래그 중에만 표시
└──────────────────────────┘
```

- ✕: 새로 만들기 (확인 모달 → 문서 초기화 → 비율 선택으로)
- 🎨: 배경 시트 (단색 / 사진) — 배경은 언제든 변경 가능
- Aa: 새 텍스트 입력
- 🖼: 스티커 시트 — [앨범에서 고르기] / [붙여넣기]
- ⬇: PNG 저장

### 터치 조작

| 동작                  | 결과                                                                                |
| --------------------- | ----------------------------------------------------------------------------------- |
| 요소 한 손가락 드래그 | 이동. 잡는 순간 `order` 맨 뒤(맨 위 레이어)로. 드래그 중 상단 바 숨김 + 휴지통 표시 |
| 휴지통 위로 이동      | 요소 축소 + 휴지통 확대 표시. 손을 떼면 삭제                                        |
| 두 손가락 핀치·회전   | 배율·회전 동시 변경. 대상은 첫 손가락이 잡은 요소                                   |
| 텍스트 탭             | 텍스트 입력 화면에서 수정                                                           |
| 빈 캔버스 탭          | 새 텍스트 입력 시작                                                                 |
| 중앙 근처 이동        | 세로·가로 중앙 가이드선 표시 + 스냅                                                 |
| 0° 근처 회전          | 0°로 스냅                                                                           |

- 캔버스 영역은 `touch-action: none` + iOS `gesturestart` 기본 동작 차단 → 페이지 확대·스크롤과 충돌 방지.
- **PC(마우스, `pointer: fine`):** 클릭으로 선택 시 Konva Transformer 핸들(크기·회전, 비율 고정) 표시. 터치 기기에서는 핸들 없음.

### 텍스트 입력 화면 (TextComposer)

```
┌──────────────────────────┐
│ [정렬] [A 배경]     [완료] │
│ ┃                        │  왼쪽 세로 슬라이더: 글자 크기
│ ┃     입력 중인 글자        │  (선택한 폰트·색·배경 스타일 즉시 반영)
│ ┃                        │
│ (Pretendard)(Jua)(손글씨)…│  폰트 선택 줄
│ ● ● ● ● ● ● ● ●          │  색 팔레트
│ ─────── 키보드 ─────────  │
└──────────────────────────┘
```

- 반투명 어두운 오버레이, 캔버스가 비쳐 보임.
- 새 텍스트는 캔버스 중앙, 배율 1, 회전 0으로 추가.
- [완료] 시 내용이 비어 있으면 블록 삭제(새 텍스트면 추가하지 않음).
- 키보드 대응: `visualViewport` 높이 기준으로 레이아웃.

### 스티커 넣기

- **앨범:** `<input type="file" accept="image/*">` → 압축(PNG/WebP, 긴 변 2048px) → 중앙에 추가
- **붙여넣기:** 버튼 탭 → `navigator.clipboard.read()` → `image/png` 등 이미지 항목 → 압축 → 추가. PC는 `paste` 이벤트(Ctrl/Cmd+V)도 지원.
- 스티커 초기 크기: 캔버스 짧은 변의 50%에 맞춘 배율.

### 실행 취소 / 다시 실행

- `Y.UndoManager`가 `blocks`, `order`, `meta.background`를 추적. `meta.ratio`는 제외.
- 제스처 한 번(드래그·핀치), 텍스트 편집 한 번, 배경 변경 한 번 = 1단계. 제스처 종료 시 `stopCapturing()`으로 묶음을 끊는다.
- **기록은 메모리에만** 있다. 새로고침·페이지 이탈 시 실행 취소 기록은 비고, 작업 결과(문서)는 IndexedDB에 남는다.
- **최근 50단계만** 유지한다. `Y.UndoManager`에 개수 옵션이 없으므로 `stack-item-added` 때 `undoStack` 길이가 50을 넘으면 가장 오래된 항목을 버린다. (삭제된 스티커의 이미지 데이터가 기록에 붙잡혀 메모리를 차지하는 것을 막기 위함)

### PNG 저장

- 가이드선·핸들을 숨긴 상태로 `stage.toDataURL({ pixelRatio })` — 논리 해상도(예: 1080×1920)가 되도록 `pixelRatio = 논리 폭 / 표시 폭`.
- 저장 전 폰트 5종 로드 완료를 기다린다.
- `navigator.canShare({ files })`가 가능하면 공유 시트(iOS "이미지 저장"), 아니면 `<a download>`.

## 6. 데이터 흐름

```
사용자 입력 (제스처·버튼·입력 화면)
   → gestures/ui 가 operations 호출 (doc.transact)
   → Y.Doc 변경 ─┬→ y-indexeddb 저장
                 ├→ UndoManager 스택 기록
                 └→ useDocSnapshot 이 스냅샷 갱신 → Konva 리렌더
```

- 드래그 중 매 프레임 문서를 쓰면 IndexedDB·UndoManager 부하가 크므로, **드래그 중에는 Konva 노드만 직접 움직이고 제스처 종료 시 한 번 문서에 기록**한다. 핀치도 같다.
  - 2단계에서 다른 사람에게 실시간으로 보여야 하면 그때 throttle(예: 50ms)로 중간 기록을 추가한다.

## 7. 에러 처리

| 상황                          | 처리                                                                   |
| ----------------------------- | ---------------------------------------------------------------------- |
| 클립보드 API 없음 / 권한 거부 | 토스트 "이 환경에서는 붙여넣기가 안 돼요" + 앨범 선택 열기             |
| 클립보드에 이미지 없음        | 토스트 "복사된 이미지가 없어요"                                        |
| 이미지 디코딩·압축 실패       | 토스트 "이미지를 불러오지 못했어요"                                    |
| 폰트 로드 지연                | 기본 폰트로 먼저 그리고, 로드 완료 시 다시 그림. 저장은 로드 완료 대기 |
| IndexedDB 사용 불가           | 메모리로만 동작 + 토스트 "새로고침하면 작업이 사라져요"                |
| 공유 시트 미지원              | 파일 다운로드로 대체. 사용자가 취소하면 무시                           |

## 8. 테스트

### 자동

| 종류                    | 대상                                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 단위 (Vitest)           | `operations`(추가·수정·맨 위로·삭제·배경), UndoManager 묶음 단위·50단계 제한, `geometry`(화면 맞춤 배율, 중앙·회전 스냅, 휴지통 판정, 핀치 배율·각도) |
| 컴포넌트 (RTL)          | TextComposer(빈 내용 완료 시 삭제, 폰트·색·정렬·배경 선택), SetupFlow(비율 → 배경 → 시작)                                                             |
| E2E (Playwright 모바일) | 비율 → 배경 → 텍스트 추가 → 새로고침 후 유지 → PNG 저장 파일 생성                                                                                     |

### 실기기 확인

iPhone Safari · Android Chrome · 카카오톡 인앱 브라우저에서 확인하고 `docs/experiments/editor-phase1.md`에 표로 기록한다.

1. 요소 20개에서 드래그·핀치가 끊기지 않는가
2. 핀치 시 페이지 확대·스크롤이 일어나지 않는가
3. 텍스트 입력 중 키보드가 올라와도 화면이 깨지지 않는가
4. 폰트 5종이 캔버스와 저장 이미지에 처음부터 나오는가
5. 누끼 붙여넣기 시 투명 배경이 유지되는가
6. 원본 해상도 PNG에 폰트·이미지가 다 들어가고, iOS 사진 앱에 저장되는가
7. 제스처 하나가 실행 취소 한 단계로 묶이는가
8. 새로고침 후 작업이 유지되는가
9. 새 글자를 처음 입력할 때 폰트가 늦게 바뀌는 것이 거슬리지 않는가 (`docs/decisions/0001-korean-font-loading.md` 재검토 기준)

## 9. 2단계로 넘길 것

- Hocuspocus provider 연결(`useEditorDoc`만 수정), 드래그 중간 기록 throttle
