# 0001. 한글 웹폰트는 preload하지 않고 쓰는 글자만 그때 불러온다

- 상태: 채택 (에디터 실험 1단계)
- 날짜: 2026-11-24
- 관련: 이슈 #11, `docs/superpowers/specs/2026-11-24-editor-phase1-design.md`

## 배경

에디터에서 텍스트 폰트 5종(Pretendard, Gowun Batang, Jua, Black Han Sans, Nanum Pen Script)을 제공한다. 처음에는 5종을 preload해서 첫 화면부터 바로 보이게 하려고 했다.

하지만 한글 폰트는 preload가 사실상 어렵다.

- 영문은 글자가 100여 개라 폰트 파일 하나가 수십 KB다. 한글은 완성형만 11,172자라 폰트 하나가 수 MB다.
- 그래서 Google Fonts는 한글 폰트를 **글자 범위별로 약 100개 파일로 쪼개서**, 화면에 나온 글자가 든 파일만 받게 한다.
- preload는 "이 파일을 미리 받아라"라는 지정이다. 어떤 글자를 쓸지 미리 알 수 없으니, 한글을 preload하려면 쪼갠 파일을 전부 받아야 한다. 폰트 4종이면 수백 개 파일, 수 MB다.
- Next 16의 `next/font/google` 폰트 정보에도 이 4종의 subset은 `latin`(일부는 `latin-ext`, `vietnamese`)뿐이고 한글 subset이 없어, 한글 preload를 지원하지 않는다.

또한 `<canvas>`는 아직 받지 않은 폰트 파일을 기다리지 않고 기본 폰트로 그려버린다. 아무 처리도 안 하면 캔버스와 저장 이미지에 기본 폰트가 나올 수 있다.

## 검토한 선택지

| 선택지                           | 내용                                                                                         | 장점                                                  | 단점                                                                                                                            |
| -------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **A. 쓰는 글자만 그때 받기**     | 영문만 preload, 한글은 실제 입력한 글자가 든 파일만 `document.fonts.load(font, 글자)`로 받음 | 가볍다. 추가 작업이 없다. 저장 이미지는 정확하다      | 새 글자를 처음 입력할 때 잠깐 기본 폰트로 보였다가 바뀔 수 있다                                                                 |
| B. 자주 쓰는 한글만 묶어 preload | KS X 1001 한글 2,350자 + 영문만 남긴 서브셋 폰트를 직접 만들어 폰트당 1파일로 preload        | 첫 화면부터 바로 보인다                               | 폰트당 약 300~600KB, 5종이면 2~3MB를 처음에 받는다. 2,350자 밖의 글자(예: 똠, 햏)는 기본 폰트. 서브셋 파일 제작(fonttools) 필요 |
| C. 섞기                          | 기본 폰트(Pretendard)만 B, 나머지 4종은 A                                                    | 첫 화면 부담이 적고 가장 많이 쓰는 폰트는 바로 보인다 | B의 제작 작업이 그대로 필요                                                                                                     |

## 결정

**A를 채택한다.**

- 영문(latin)만 preload한다.
- 캔버스에 그리기 전, 이미지로 저장하기 전에 텍스트 블록의 실제 글자로 필요한 폰트 파일을 받는다(`ensureFontsLoaded`).
- 폰트 파일이 새로 로드되면(`document.fonts`의 `loadingdone`) 글자 폭을 다시 재고 다시 그린다.

## 이유

- 사용자 대부분이 모바일(카톡 공유)로 들어온다. 첫 화면에서 수 MB를 받는 비용이 크다.
- 폰트 5종은 디자인 단계에서 바뀔 수 있다. 지금 서브셋 파일을 만들면 다시 만들어야 할 수 있다.
- A의 단점(새 글자 첫 입력 때 잠깐 기본 폰트)이 실제로 거슬리는지는 실기기에서 확인해야 판단할 수 있다.

- 디자인 단계에서 폰트 목록을 확정할 때
